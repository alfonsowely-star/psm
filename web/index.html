Agent 配平 把新老两拨人配成可比的两队

新手引导 · 怎么填

工具做一件事：把「新 agent 处理的进线」和「老 agent 处理的进线」，按维度配成可比的两队，输出谁配谁。

原理 · 为什么不能直接比

新 agent 不是随机上线的，它先推给了特定的人（高会员、特定意图等）。所以「新 agent 处理的进线」和「老 agent 处理的进线」本来就不是一拨人，直接比它们的结果不公平。

工具做的事：给每条「新 agent 的进线」，在「老 agent 的进线」里找一个其他维度上最像的，配成一对。配完后两队就「长得一样」了（除了一个是新、一个是老）。你再拿这两队去比任何结果（转人工、满意度），差异才能归到 agent 本身，而不是人的差异。

打个比方：新教练只教尖子生、老教练教普通生。直接比考试成绩，新教练必胜——但那是学生底子好，不是教练好。工具就是给每个尖子生，在普通生里配一个「基础、学习时长都一样」的，配完再比谁进步大，才公平。

数据：一行 = 一条进线（实例）

列必需含义
session_id / user_id建议实例 id（配对结果的标识）
agent必需谁处理的：新 agent=1，老 agent=0
member_level 等维度用来配对的进线特征，多选无妨

映射列怎么填

字段怎么填
实例列 id_col选标识每条进线的那列（session_id 或 user_id）
处理方列 treat_col选「谁被分到新 agent 灰度组」那列（0/1），不是实际谁处理
新 agent 取值新 agent 在这列里的值：0/1 填 1，old/new 填 new
维度 cov_cols勾「进线时就确定」的特征，多选无妨
三条铁律：① 处理方列是唯一不可缺的列；② 「新 agent」填「是否被分到灰度组」（可以触发），不要填「实际谁处理」（触发过）——新 agent 会把难问题转人工，按实际处理算会把难问题踢掉、只剩简单问题；③ 维度只能放「进线时就已知」的特征。
